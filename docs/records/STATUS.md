## PR 007 verification

On Linux x86_64 with Rust 1.100.0 and an Intel Xeon host, `cargo test --workspace --locked` passed 27 Core tests, 11 protocol library tests and 2 protocol integration tests. The new tests publish protocol events through the scheduler and bus. They check contiguous delivery, admission waiting, full-queue rejection, coalesced `lost` and `filtered` gaps, cross-batch holes, duplicates, priority, cooperative cancellation, timeout signaling, panic isolation, subscription limits and joined threads. On Linux the joined thread IDs no longer carry that scheduler's thread name. The check records each thread's start time, so a recycled thread id is not treated as a leak, and the test waits up to two seconds for the kernel to drop the task entry. A release run delivered 20,000 observations in 39.925 ms, about 501,000 events per second, with no losses. Debug runs of that test stayed inside the 10 second bound. `cargo build --locked -p winstrata-core` reported no warnings. The lockfile adds only the existing `winstrata-protocols` crate to Core. No new external crate was added.

## PR 012 verification

On Linux 6.12.113+ x86_64, Rust and Cargo 1.100.0, and 4 Intel Xeon virtual CPUs, `cargo test --locked -p winstrata-core --lib -- --test-threads=8` passed 35 Core tests, 7 of them hybrid-storage tests. `cargo test --locked --workspace -- --test-threads=8` also passed those 35, 11 protocol library tests and 2 protocol integration tests. `cargo build --locked -p winstrata-core` reported no warnings. `cargo check --locked --target x86_64-pc-windows-msvc -p winstrata-core` type-checked the Windows target. It did not run Windows tests or link a Windows program.

The hybrid tests wrote and read back objects, relations, events, metrics, risk-tagged PCAPNG captures and snapshot metadata. The segment test set the segment limit to 256 bytes. The index test confirmed that a payload token occurs once in the directory tree and that the journal does not keep a second copy of the body. The capacity test compared regular-file lengths in the six directories. The corruption test changed a token inside a committed payload. The same-process query returned `InvalidData` and did not return the body. Reopen rolled that commit back (`rolled_back_commits` at least 1), kept the earlier object, and left the damaged token out of the file. The implementation also drops later complete journal frames that were not applied. This test did not write another successful commit after the damaged one. A torn journal tail and a torn segment tail were truncated on reopen, with `rolled_back_commits` equal to 0. An untagged capture was rejected before any write and left the capture directory empty. Retention days were stored and read back after reopen, and the test data was not deleted. A repeated event sequence and a failed batch did not extend committed bytes. After the journal was made unwritable, `commit_hybrid` returned permission denied, the session became `NeedsDirectory` and live mode stopped. Restoring the mode and selecting the directory again left the earlier object in place and left the rejected object absent. An event delivered by the bus was stored by the caller and read back. Migration copied that record and left it in the source.

A release build committed 2,000 events in 17 ms. The test bound is 30 seconds. The same test took 145 ms in debug. That is one commit and one sync, not a sustained ingest measurement. `reserve(u64::MAX)` returned insufficient space through the existing capacity check and did not fill a physical disk. This host has no `tshark`, `tcpdump` or `editcap`, so no external PCAPNG tool was run. The test checks section-header magic `0x0A0D0D0A` and reads the packet bytes back with the in-tree parser.

`cargo dev doctor` and `cargo dev verify` were not run on this host because the active Node.js is v22.23.4 and the pinned engine is 24.22.3. The `cargo test --locked --workspace` command used by verify was run directly. The lockfile adds no new external crate. Windows tests were not run on this host. Windows 10/11 client behavior, ReFS, encryption, E2E-05, E2E-09 and E2E-10 were not run.

On `dfe59001d1647d8093fe8a90881efdc9a397f045`, GitHub Workspace, Linux workspace and Windows workspace checks succeeded. The Linux job ran the repository workspace script. The Windows Server 2022 job ran `cargo test --locked --workspace` and succeeded. The unwritable-journal test is compiled only on Linux. `winstrata/merge-policy` reported “Plan 008 must merge before plan 012”. That is the roadmap order gate, not a hybrid-storage defect, and this plan does not change the gate.
