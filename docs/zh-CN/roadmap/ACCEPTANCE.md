## 性能目标与测试口径

以下为已确认目标，须以真实整体验收验证，不能宣称现已达成。以 Windows 11 x64、8 核、16 GB、NVMe SSD 为性能验收方案的候选参考，PR 000 应定义具体代表性硬件、Windows 版本、典型插件组合、事件/网络负载、统计窗口及采样方法，并由用户审核。禁止通过少采集、降低精度、减少功能或未统计子进程制造达标。

| 指标 | 目标 |
|---|---:|
| 常规后台监视总内存 | ≤ 150 MB |
| 常规后台监视 CPU 总占用 | ≤ 1% |
| 常规完整 GUI 总内存 | ≤ 350 MB |
| 完整运行产物体积 | ≤ 250 MB |
| 冷启动时间 | ≤ 3 秒 |
| 禁用插件专属资源 | 接近零占用 |
| 未风险标记原始包持久化写入量 | 0 |
| 无效重复读写 | 尽可能消除并实际评估 |

测量范围应包括 Core、GUI/WebView、服务、插件进程、运行时及可归因内核开销；区分私有工作集、共享内存、提交量，避免重复计数。CPU 按整机总能力口径，注明平均值、峰值、测试时长；记录 I/O、写入放大、数据库增长、吞吐、延迟、采集缺失、启动及产物大小；必须可复现。性能预算不是硬编码的任意限制，也不是峰值保证。初次全局基线、高频抓包/扫描、大型快照、用户脚本、高负载分析应单独测试和显示峰值；发现明显退化需修复或审批。

建议以稳定后的 10 分钟为一个后台/GUI 测量窗口，每秒采样并重复三次，冷启动在重启或经验证的等效冷状态下运行五次。记录各次冷启动、平均和峰值、Windows 构建号、WebView2、工具、硬件型号、启用插件和负载。产物计入运行所需的官方插件、运行时与共享依赖；可选调试符号、系统 WebView2、用户数据和额外扩展、工具及缓存单独报告。具体方法由所有者审核。

工程估算（非实测，不能作为完成证据）：常规后台 80–160 MB / 0.3–1.5% CPU；常规 GUI 180–320 MB / 1–3%；全部常规监视插件后台 150–300 MB / 1–4%；高负载更高。完整运行产物估计 90–230 MB；开发版包含符号可能 300–800 MB；不含系统 WebView2、用户数据、额外第三方插件、工具链及缓存。最终体积口径需明确包含实际运行所需的官方插件/运行时及共享依赖；不得通过拆包规避 250 MB 目标。按需加载、复用系统 WebView2 等属于候选优化，具体选型需批准。选择性抓包减少存储而不消除抓包解析 CPU 开销。

## 统一测试与验收体系

测试以真实用户操作为依据，优先真实 Windows 系统、整体端到端、跨插件集成和长时间运行。少量有价值的单元/Mock/契约测试用于关键算法和异常路径，不大量制造 Fake 测试、一次性脚本或覆盖率数字。统一复用测试资产；测试本身需有真实用途。不能用模拟数据、编译成功、静态截图、阅读代码或子 Agent 自报替代运行证据。未验证必须明确标记，未通过不能标完成。

| 场景 ID | 真实用户操作及验收重点 |
|---|---|
| <a id="e2e-01"></a>E2E-01 | 从现有正确依赖启动开发版；首次引导选择语言、D 盘/手动存储、插件、范围、加密、自启动；无 D 盘不自动写 C 盘；实际建立基线 |
| <a id="e2e-02"></a>E2E-02 | 用户选择一个本地磁盘，创建/修改/移动/删除真实文件，修改测试键值及 PATH；在 GUI 查询位置、进程、前后值和历史，不监视未选区域和其他用户私人活动 |
| <a id="e2e-03"></a>E2E-03 | 安装、运行、更新、卸载一个真实合法测试软件，自动识别与手动会话，查询进程树、服务、依赖、签名、注册表、环境变量、残留及占用；不误把共享组件判为独占 |
| <a id="e2e-04"></a>E2E-04 | 产生真实入出站流量、访问授权局域网、切换可用网卡/虚拟接口，查看拓扑、连接、协议及流量；标记一部分，导出风险包并证明未标记原始包从未写磁盘 |
| <a id="e2e-05"></a>E2E-05 | 用合法实际采集数据触发抓包 1 GB 和日志 2 GB 告警（可先通过小阈值加速验证流程，再验证实际默认阈值）；取消后分别按 1 GB、500 MB 阶梯提醒，重启状态不丢，确认清理和索引一致，GUI/脚本改阈值；未确认不删 |
| <a id="e2e-06"></a>E2E-06 | 启用/禁用/替换真实插件，安装社区扩展，动态页面与依赖、撤权、热更新及回退；其他无依赖插件持续，历史数据保留，运行资源释放；隔离恶意行为测试不伤真实系统 |
| <a id="e2e-07"></a>E2E-07 | 用户或外部 Agent 创建实际脚本，测试/执行/触发/暂停、日志和故障；创建手动快照并比较，只有用户定义自动策略才可运行；过滤脚本失败回落，默认无预设 |
| <a id="e2e-08"></a>E2E-08 | 查看 CPU/GPU/内存/SSD 等真实计数器、StrataHealth 和预算；人为提高合法负载，验证延迟/限额/暂停/恢复、异常与丢失标识；记录写入量和性能 |
| <a id="e2e-09"></a>E2E-09 | 全局搜索某个真实软件，查看所有来源、时间线缩放/回放、关系图、数据来源及不确定性；导出 JSON/CSV/HTML/PCAPNG；回放不改系统 |
| <a id="e2e-10"></a>E2E-10 | 锁定/解锁界面，持续后台监视，加密备份、迁移、恢复与失败回退；无权限插件不能读取密钥/数据，恶意导入不能逃逸路径 |
| <a id="e2e-11"></a>E2E-11 | 实际 Windows GUI：三套内置主题切换/保存/重启恢复，验证指定组件及排版复用、玻璃材质与动效性能、插件页面一致性；切换语言、缩放窗口、拖拽/保存单首页、查看空数据/失败/不支持状态、关闭窗口询问、托盘继续、完全退出、实时/历史切换、重新启用 |
| <a id="e2e-12"></a>E2E-12 | 本机 Agent 通过真实 MCP 获取数据、动态开发安装真实插件、编辑脚本、调用已授权功能；远端拒绝、撤权生效、禁用注销、无内置 Agent；正式发布确认且不上传监视数据 |
| <a id="e2e-13"></a>E2E-13 | 在隔离测试 Windows 运行无害测试进程/文件/软件，验证 StrataRescue 默认关闭、临时通道、仅许可操作、任意命令/系统配置越权被拒绝、关闭撤销、审计与准确结果 |
| <a id="e2e-14"></a>E2E-14 | 真实 Windows 更新、服务、驱动、安全状态及证书变化（授权测试环境），不修改用户安全配置；对不可观察事件显示限制；验证错误和缺失状态 |
| <a id="e2e-15"></a>E2E-15 | 长时间运行、突发事件、驱动/插件异常、磁盘不足、断开存储、资源压力、异常退出等；检查系统稳定性、无循环记录、无静默丢失、可恢复、无泄漏 |
| <a id="e2e-16"></a>E2E-16 | 实际合并候选和主分支回归，防止旧功能回流、已修复错误复发；核对文件树、文档、依赖路径、配置、权限、版本和真实产物；验证所有适用门禁 |
| <a id="e2e-17"></a>E2E-17 | 官方 GUI 仍安装时，安装、启用、禁用、更新并卸载一个真实的第三方 GUI 插件，然后恢复默认界面。修改主题、颜色、材质、字体、动效、交互、布局、导航、侧边栏、顶部区域和仪表盘。替换共享组件及其他插件的界面呈现，再替换整个界面。后台监视继续，无关服务保持运行，已存储的数据仍在。只运行一套完整 GUI 渲染环境。插件由现有市场管理。 |
| <a id="e2e-18"></a>E2E-18 | 从该第三方 GUI 尝试绕过权限、隔离、救援授权和删除确认。这些交互由可信宿主执行。伪造的授权被拒绝。 |
| <a id="e2e-19"></a>E2E-19 | 提交中的每个官方 GUI 和官方插件组件或布局文件都有来源登记行。上游仓库、修订、源码路径、许可证、复用方式和修改内容与文件相符。缺少上游组件时必须是所有者已批准的缺口。未经批准的视觉重写视为失败。 |

## 可替换 GUI 的方案

实现 E2E-17 或 E2E-18 之前，开发 Agent 先调研并验证技术路线，再由所有者批准。本验收计划不选定该路线。系统架构里已经点名的候选仍然未获批准。计划 053 不为方案或 GUI 实现再增加计划编号。

所有测试应使用经授权的用户环境或隔离 Windows 测试环境；高风险测试不得在真实个人电脑未经许可执行。按环境记录 Windows 版本、硬件、驱动、构建 commit、工具链、实际命令、步骤、预期/实际、失败及重验、证据位置。大型原始抓包、系统日志或隐私数据不提交 Git。可记录安全摘要和可复现步骤。

每个 PR 验证当前变更以及已实现能力的统一整体回归；按当前环境构建，未执行另一平台构建如实标注。真实 GUI、驱动或系统功能所需的验证不能因缺环境而假称通过。每个模块、长会话和 PR 更新文档；合并后实际主分支回归和阶段验收。测试方案及量化门限在 PR 000 明确，涉及实现或依赖的细节经审批。

## 最终交付判定

WinStrata V1.0 开发版完成须同时满足：

1. 25 个官方插件的全部已批准业务能力真实实现，默认附带、不可卸载、用户选启、独立生命周期；StrataRescue 默认关闭、仅临时受限通道。
2. 核心通用、模块解耦、共享采集/存储/配置/依赖/调度、混合运行时、市场、MCP、脚本、GUI 和真实数据端到端联动，无内置 Agent、无云依赖或监视数据上传。GUI 必须满足 [§9](../architecture/FRONTEND.md#section-9) 的指定开源来源、三套内置主题、组件复用红线及排版适配约束，并通过真实交互和性能验收。E2E-17、E2E-18 和 E2E-19 在所有者指定路线图行之前保持开放。
3. Windows 10/11 x64 实际运行支持及 Linux/Windows 构建能力有真实证据；按开发者环境负责，不强制每 PR 双端验证；不可观测能力如实说明。
4. 风险抓包留存、日志/抓包提醒、授权清理、D 盘手选回退、自身过滤和低 I/O 保护与批准策略一致；加密、备份、迁移及保留数据完整性经过测试。
5. 真实用户操作、统一整体回归、长期稳定性、安全及性能验收达到批准标准；不得以测试数量、假数据、代码存在或构建成功代替真实功能证据。
6. 全需求矩阵逐项核对，64 项 Agent 规范执行，错误及技术债务真实维护；确认缺陷未修复不得完成验收。文档、代码、进度、依赖、配置及文件树一致。所有者合并 AG-64 之后才把它计入。
7. 全部 PR 按已批准的合并顺序由所有者实际合并并完成主分支验证。最终产物、运行/构建指南、SDK/接口、双语文档和必要调试资料完整；所有者最终审核。

**第一条执行指令**：先检查工具、GitHub 身份与项目目录，输出前置清单；在所有者确认仓库创建目标后建立最小公开仓库，立即进入 PR 000。未经 PR 000 合并不得正式开发功能。不得擅自扩大已冻结的产品范围。
