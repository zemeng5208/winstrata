# 测试规范

[English](../../standards/TESTING.md) · [文档索引](../INDEX.md)

<a id="ag-15"></a>

### AG-15 真实环境、整体测试优先

区分开发/测试/真实用户环境，高风险驱动/注册表/网络/救援优先隔离 VM 或专用环境；真实电脑危险测试须明确授权。禁止大量 Fake/Mock/Stub、低价值覆盖率测试、每简单函数机械测试、大量独立一次性脚本和模拟通过冒充真实。整体真实用户流程、跨模块集成、端到端、长期稳定性、性能优先；必要关键单元及契约测试按需保留。统一复用测试框架。

<a id="ag-16"></a>

### AG-16 全局回归与合并前验收

每 PR 验证新旧功能及实际合并候选，统一整体回归、插件协作、兼容性、稳定性、性能、前序修复和废弃回流。发现问题修复重验；真实结果及未验证项同步模块和全局文档。不能执行不标通过。前序成果必须保留。

<a id="ag-17"></a>

### AG-17 根因修复与全局同类问题排查

发现缺陷查根因，扫描全仓库同类及相似错误、公共组件和上下游；范围内修复，范围外报告并审批扩围，不擅改或忽略。可委托子 Agent 并行排查；整体回归、错误/文档同步，未修复确认缺陷阻断合并。

<a id="ag-18"></a>

### AG-18 性能退化及资源开销

每 PR 实际评估适用的 CPU/内存/I/O/存储增长、驱动、吞吐/延迟、GUI、插件、启动/产物，与可比较的前序环境及负载对比。维护基准；明显退化查根因并优化，未经批准不接受。不得少采集、降精度、丢事件或改变口径伪造提升。优先真实场景，减少无价值微基准和无效 I/O、硬件写入放大。量化目标见 [§10](../roadmap/ACCEPTANCE.md#section-10)，未实现阶段如实记录。

<a id="ag-37"></a>

### AG-37 真实 GUI 验收

涉及 GUI 必须实际启动 Windows 应用并交互，不靠静态截图、编译或审查代替。真实后端、无空按钮；验证缩放、切换、刷新、插件热插拔、语言、加载/空/权限/失败、不支持、长期响应和内存。按 [§9](../architecture/FRONTEND.md#section-9) 验证指定组件复用、三主题切换与持久化、排版一致性和玻璃/动效开销，记录证据；无真实 GUI 环境标未验证，不假称通过。

<a id="ag-52"></a>

### AG-52 未验证假设

关键假设单独记录影响、验证方法、状态；区分事实/推断/假设。先小规模真实可行性验证，尤其 Linux 驱动工具链、隔离、抓包、高权限 IPC；不在未经验证基础上大规模开发，不把 PoC 当正式功能。失败分析、备选审批，清理无用原型，同步架构、规范和路线图。

<a id="ag-53"></a>

### AG-53 真实用户场景

验收从真实用户使用出发，启动、配置、操作、结果全链路，真实 Windows/软件/网络/数据；不按自己实现反向设计易通过测试。正常、误操作、权限不足、异常退出、资源不足等；记录步骤、预期、实际、问题，修复后重跑完整流程。功能、体验、真实性、性能及稳定性都检查。
