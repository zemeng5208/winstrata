# Agent 工作流

[English](../../standards/AGENT_WORKFLOW.md) · [文档索引](../INDEX.md)

<a id="ag-07"></a>

### AG-07 多 Agent 协作

主 Agent 明确子任务、文件修改边界、接口契约和验收；未经协调不同时修改同文件。可用独立 Worktree/分支；子 Agent 遵守全部适用规范，不扩大范围。主 Agent 实际审查 diff、测试与文档，集成并承担最终质量，不能直接相信自报完成；不破坏 PR 顺序。按复杂度分配模型。

<a id="ag-11"></a>

### AG-11 自主开发与用户干预

已批准范围、方案、验收明确时自主连续完成实现、构建、排错、测试、文档，不为小步骤反复问，不以计划代替执行，不无故停止。架构/技术栈/依赖/复用项目/范围/需求冲突、重大阻塞、高风险或不可逆操作、PR 合并等须审批。持续报告有效进度，自主执行不等于自主决策。

<a id="ag-20"></a>

### AG-20 Token 与模型成本

高能力模型处理架构/内核/复杂逻辑/安全；廉价子 Agent 优先文档、资料、扫描、简单重复任务；按需读取上下文，复用仍有效的结果，变更导致失效须重验。避免重复输出，上下文耗尽前保存交接。不得以成本牺牲质量、测试、安全和完整文档。

<a id="ag-50"></a>

### AG-50 责任延续及强制交接

开发者负责其 PR 的实现、CI、审查、冲突、回归修复、验收，不因提交/会话结束卸责。被迫中断或验收转交时，接手者读规范/交接、核对现有代码、工作树和真实测试，沿用现有实现及批准方案继续直到当前任务全量验收，再做其他任务；不因偏好推倒重做、跳后续 PR 或忽略遗留错误。现有缺陷按根因/审批处理。

<a id="ag-51"></a>

### AG-51 会话收尾（可委托廉价模型）

长会话结束，无论完成与否，检查工作树/文件树、实际构建测试、全局关联文档、进度/PR、错误记录、临时产物、阻塞及下一步，形成可恢复交接。优先廉价子 Agent 整理，主 Agent 提供真实材料并核实；子 Agent 不擅改实现、规范或验收；不可用时自己执行，不省略。

<a id="ag-57"></a>

### AG-57 有效汇报

只报告实际进展、技术发现、测试、错误、阻塞和待决；不重复需求/空计划/虚假百分比/夸大成果/防御辩解讨好/大量原始日志。区分已实现、已验证、待验证、未完成；日常简洁，关键问题详细，完整记录维护在仓库。

<a id="execution-checklist"></a>

## 执行检查清单

以下清单用于每个任务，不得提前打勾或声称执行过；实际输出填写状态及证据。

### 开发前（向用户输出）

- [ ] 恢复规范、架构、需求、前序 PR 和交接；确认当前任务编号及批准范围。阅读[未验收事项登记](../records/OPEN_ITEMS.md)中每一项仍开放的记录，以及[错误登记](../records/ERRORS.md)中每一项未解决错误。
- [ ] 核对分支、基线 commit、工作树、并行任务及顺序依赖，保护他人未提交文件。
- [ ] 核实工具/权限/当前环境/网络/子 Agent 可用性；明确限制。
- [ ] 检查已批准项目级依赖完整性、版本、锁文件及实际解析路径，缺失按规范补齐。
- [ ] 搜索现有代码、接口、测试、共享能力及候选开源复用；新依赖/方案申请审批。
- [ ] 明确实施计划、接口/安全/性能影响、真实验收场景、关联文档及需批准事项。

### 开发中

- 仅在批准范围内连续开发，不因小步骤询问；发现阻塞或重大变更申请审批。
- 核实真实接口与假设；维护错误、模块进度、测试证据和文档全局关联；可委托低成本整理。
- 复用共享基础设施，保持项目依赖、配置及目录集中；防止假功能、空壳、临时后门、无意义脚本。
- 真实用户流程验证，发现问题全局排查、修复重验；真实限制如实记录。

### PR 申请前

- [ ] 当前范围完整实现，无假数据、假测试、调试污染及未解决确认问题。
- [ ] 当前环境构建、真实 Windows/GUI（适用时）、整体回归、实际性能及安全检查，未执行项按 [AG-62](../AGENTS.md#ag-62) 的字段写入未验收事项登记。确认缺陷写入错误登记，不得记成限制。
- [ ] 全仓库架构/依赖/配置/复用/文档/文件树审计；清理本次无用中间产物。
- [ ] 最新 main 合并候选与语义冲突、前序删除回流、修复复发检查；自审及重验证据。
- [ ] 实际变更文件、需求矩阵、错误、进度及全部受影响文档同步。
- [ ] 提交合并顺序申请、前置、风险及验收报告，由所有者合并。

### 合并后或长会话结束

- [ ] 获取真实主分支状态（已合并时），检查 CI/回归及下一顺序门禁；发生回归时按 [AG-63](../AGENTS.md#ag-63) 更新错误记录、需求矩阵和验收状态，并阻断下一顺序合并。再次检查每一项仍开放的未验收事项。
- [ ] 更新权威进度、需求、错误、关联文档及实际证据，遵循 PR 规则。
- [ ] 清理无用中间产物，明确工作树、未提交成果、剩余任务、阻塞及交接责任。
- [ ] 如需交接，接手者沿当前实现完成整个当前任务后才做其他任务；文档收尾可委托廉价模型并核实。
