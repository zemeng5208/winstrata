# 开发规范

[English](../../standards/DEVELOPMENT.md) · [文档索引](../INDEX.md)

<a id="ag-01"></a>

### AG-01 架构决策权

严格遵循已批准架构、技术栈、接口及需求。禁止擅自变更、替换、删减、降低标准。发现缺陷或阻塞停止受影响工作，提交问题、真实证据、影响与备选，获得所有者批准再改；不受影响工作可继续。困难不构成降低标准的理由。

<a id="ag-02"></a>

### AG-02 禁止规避与妥协

追查根因。禁止删/跳/弱化测试、关闭检查、空实现、硬编码结果、虚假数据、吞掉异常、伪造成功、擅自降低依赖版本/兼容/性能/安全要求、临时补丁掩盖缺陷及未验证标完成。无法解决如实报告，保留证据。

<a id="ag-03"></a>

### AG-03 任务范围与修改边界

只修改当前批准 PR 范围；不得无关重构、改公共接口、引入依赖、变更目录、提前实现后续 PR、覆盖他人未提交成果或混入无关修改。范围外问题记录并申请批准；提交前审查完整 Git Diff。

<a id="ag-04"></a>

### AG-04 前置检查与实时文档同步

开发前阅读根及相关模块 AGENTS/架构/接口，检查分支、工作树、现有代码/测试、PR 顺序依赖、任务冲突、工具/依赖路径、计划及验收和文档影响；向用户输出实际检查清单、状态、问题和证据。条件不满足不得启动受阻任务。代码/接口/配置/依赖/行为变化同步更新相关文档、路线图和进度，同 PR 提交；文档不符即未完成。禁止修改规范掩盖错误，文档一致性纳入质量门禁。

<a id="ag-09"></a>

### AG-09 可维护性与技术债务

避免重复代码、巨型职责混乱文件/函数、循环依赖、跨层耦合、无意义抽象、硬编码配置、死代码、废接口及未批准临时实现。接口职责、类型、错误和文档清楚。技术债务记录原因、风险、影响、修复建议；范围外审批并纳入有序路线图，不隐藏。复杂度量化阈值实测审批。

<a id="ag-10"></a>

### AG-10 主动质疑与真实性

不迎合、隐瞒缺陷或默认已批准设计绝对正确。发现冲突、风险、不可行、性能问题和更优方案，提供事实/推断/假设区分、真实依据及备选优缺点；用户最终决定。批准变更同步相关文档及 PR 计划。

<a id="ag-21"></a>

### AG-21 功能完整性

完整实现当前批准 PR；禁止擅自 MVP、基础版冒充完整、以未来完善/时间/难度/Token 推迟当前应交付功能。批准的阶段各自达成验收；无法实现报告阻塞，不擅自删减，未达标不申请合并。

<a id="ag-22"></a>

### AG-22 正式与调试代码隔离

禁止临时调试接口、开发后门、权限绕过、测试硬编码、个人绝对路径、无条件高频日志和已无用途的临时代码进入正式实现。日志有等级及条件，开发工具独立，调试不污染真实性和性能。开发版也按正式安全稳定标准。

<a id="ag-26"></a>

### AG-26 禁止过度工程化

满足要求前提下选简单可靠可维护方案；不创建无用模块、接口、抽象、依赖、配置、脚本、碎片文档，不为假设需求增加复杂度。优先复用批准基础设施/开源；模块明确真实用途，不借简化削弱需求。

<a id="ag-31"></a>

### AG-31 全仓库复用

新功能先检索全仓库已有组件、工具、结构、采集、数据库、权限、协议、UI 和服务。能复用必须复用，公共扩展检查上下游；公共能力一套权威实现、事件原则上采集一次。发现重复记录并申请重构，不为复用强耦合不同职责。同步 SDK/测试/文档，纳入前置及审查。

<a id="ag-33"></a>

### AG-33 删除与中间产物

删功能递归清理实现、入口、组件/路由、配置、权限、翻译、专属依赖/测试/构建、插件/SDK/MCP/文档；保留公共能力及历史决策。检查残留引用、孤立文件及回流。开发中清理无用中间产物、临时补丁/测试/备份/Worktree 等；模块/PR/长会话结束检查完整工作树和文件树（含忽略项），清理本次无用物并记录。禁止无差别删除用户数据和他人成果；保留必要复用缓存。

<a id="ag-34"></a>

### AG-34 数据真实性

展示、统计和分析有真实来源，事件可追溯采集接口/原始记录，统计有计算方法/范围/时间。区分实测、推断及可信度、缺失/失败/不支持；不以 0、默认、随机、虚构或历史缓存冒充实时。精度/覆盖真实，GUI/导出/插件/MCP 语义一致，整体测试验证。

<a id="ag-38"></a>

### AG-38 开发工具集中

统一入口管初始化、构建、运行、测试、检查、性能和清理；双环境尽可能相同命令/参数/输出。复用现有工具，不散布重复/一次性脚本；临时工具用完清理，正式工具有职责、错误及文档，遵循 PR 和测试，不污染源码。

<a id="ag-41"></a>

### AG-41 全局架构审计

每 PR 完成扫描全仓库职责、依赖方向、重复基础设施、插件/Core 耦合、接口绕过、集中依赖/配置/工具/存储、文件树、安全及架构文档。廉价子 Agent 可扫描，主 Agent 核实并记录；架构违规修复重验，阻断后续合并，防止渐进式腐化。
