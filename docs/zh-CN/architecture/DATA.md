## 网络监视、风险标记与留存

### 7.1 网络可观测性

覆盖可访问的物理/虚拟网卡、VPN、TUN、Loopback；IPv4/IPv6、TCP、UDP、ICMP、DNS、HTTP、TLS、QUIC 等可观察解析；入站/出站流量、端口、连接、所属进程/软件/服务、网络状态、系统代理、防火墙及拓扑。用户授权范围内支持主动发现局域网设备、MAC/厂商、端口、服务、路由、上下线和异常分析，配置范围/频率/资源；不实施攻击或流量篡改。

拓扑区分真实发现与推断，不能保证发现不可见物理链路或整个局域网所有流量；加密内容不能凭抓包自动解密。完整抓包能力指实时可观测能力，不代表全部原始包永久保存。

### 7.2 风险标签与原始抓包（最新规则）

1. StrataNet 实时采集、解析、归因；数据进入有界内存缓冲，避免直接落盘。
2. StrataTag 支持手动、用户脚本、其他插件依据及本机 Agent 标记；记录来源、时间、理由、可信状态。通用标记可用于进程、文件、软件、注册表、系统事件等；无内置病毒库。
3. 仅风险标记命中的原始网络包（及明确关联、受规则控制的上下文）允许持久化，PCAP/PCAPNG 查询及导出。未标记包不写磁盘，缓冲期满释放，不采用先写后删。
4. 缓冲上限与保留时间可配置；无法保留或迟到标记时如实提示，释放后不可恢复；未标记不等于安全。禁用标记插件时不能退化为全量落盘；无有效风险标签就不保存原始包。
5. 标记、过滤、资源限制均有可追溯的状态；实时统计可用，历史未标记包不可查询。用户主动过滤与采集丢失明确区分。

**待审批**：是否持久化未标记流量的轻量连接元数据（IP、域名、进程、时间和流量大小）。独立的可配置元数据和聚合历史是候选方案，须计入适用的日志容量。未标记的原始包始终不写入磁盘。计划 011 在[网络源](NETWORK-SOURCES.md)实现用户态观测和选择性原始包门禁。它不持久化未标记连接元数据，也不导出 PCAPNG。

## 存储、过滤、清理与硬件保护

### 8.1 混合存储架构

| 数据 | 存储形式（设计方向） |
|---|---|
| 软件档案、配置、对象与关系 | SQLite 等结构化存储 |
| 高频系统监视事件 | 分段追加式存储 |
| 资源时序指标 | 压缩时序存储 |
| 风险标记原始网络包 | PCAPNG/PCAP 分段 |
| 用户系统快照 | 完整及增量状态/元数据，不保存文件内容历史 |
| 全局查询 | 统一索引，原始记录仅存一份 |

Core 管理所有存储、查询、权限、加密、备份、保留、迁移、索引及专用格式；插件声明数据结构，不建立各自重复数据库。必要性能缓存可以保留，但可计算数据不无意义重复持久化。数据写入和读取必须支持一致性、失效引用处理和故障诊断。

默认数据根目录 `D:\WinStrata\`，可在 GUI 更改；D 盘不存在、不可写或空间不足时用户手动选择，不自动回退 C 盘。有效目录未选定前不开始需持久化的任务。运行时设备不可用时告警、不擅自切换。迁移校验完整性并保留原始数据直至确认成功；配置定位、运行数据及共享组件路径均由统一解析机制管理。目录结构候选：

```text
D:\WinStrata\
  data\databases\
  data\events\
  data\metrics\
  data\captures\
  data\snapshots\
  data\indexes\
  plugins\
  runtimes\
  config\
  logs\
  backups\
  cache\
```

数据目录与源代码、构建目录独立。必要的最小系统注册/配置定位信息与大体积数据分开，实际 Windows 路径方案需验证，不要求所有系统组件安装到 D 盘。路径、容量、文件系统能力、权限和迁移风险必须在 GUI 如实呈现。

计划 012 把上面 `data` 下的六个目录放进每个用户的私有目录。已实现的布局、读写、分段、索引、容量统计和损坏回退见 [Core 存储](CORE-STORAGE.md)。这次没有加入 SQLite 包，结构化记录使用版本化分段。计划 013 在这里增加可选加密、备份、恢复和加密迁移。删除和容量清理仍属于计划 030。

### 8.2 数据保留与容量告警（最新规则）

监视数据默认永久保存，原始抓包受第 7 节风险标记前置条件约束；支持独立设置各类数据保留天数。容量提醒、清理授权及已配置保留策略必须协调，禁止无授权自动清理。自动清理脚本不预设；用户定义保留期限或清理策略不得被解释为绕过明确的容量弹窗确认。实际期限到期处理的授权语义在 PR 000 明确，未获批准不擅自删数据。

| 类别 | 默认首次提醒 | 取消后的再次提醒增量 | GUI / 脚本 |
|---|---:|---:|---|
| 持久化原始抓包 | 1 GB | 1 GB | 可修改 |
| 全部保存的日志数据 | 2 GB | 500 MB | 可修改 |

阈值均为用户确认清理的强制提醒线，而非不可突破的硬上限，因为用户明确允许取消并继续累计。两类独立计算，不重复计入抓包。建议单位统一为十进制 GB/MB，最终计量单位和“全部日志”涵盖结构化事件、指标、索引/备份的边界需在 PR 000 明确，避免用分类规避限制。不能将计量口径当成已批准实现。

- 超过首次阈值弹窗，展示类别、当前实际占用、清理策略、预计释放空间、取消后的下一提醒线；确定才清理，取消继续保存并按增量再次提醒。无操作不自动同意。
- 告警状态持久化，重启不重复弹窗或丢失累计状态；清理后重新核算。阈值动态修改、一次跨过多个阶梯、清理后仍超标、后台托盘模式等边缘行为由开发 Agent 提案并验证。
- StrataStorage 支持时间、风险、期限、容量、类别、手动选择、用户保护标记及脚本自定义清理；默认具体删除选择尚未锁定，执行前显示真实范围。脚本和 MCP 能修改配置、分析及生成清理策略，不得绕过用户确认。
- 关闭 StrataStorage 仍保留 Core 基础容量告警及必要保护；无可用清理策略时提示启用插件或按已授权的安全方式操作，不擅自删数据。
- 磁盘空间不足、达到物理写入限制或用户设置的资源预算时警告；不能继续保存则明确记录缺失/暂停状态及影响范围，禁止静默丢失或自动迁往 C 盘。
- 仅清理 WinStrata 自身管理的数据，不清理外部软件或 Windows。删除后同步索引、关联记录及必要审计，优先分段删除，不逐条重建数据库。避免清理本身造成持续告警循环或大量写入。

### 8.3 默认过滤和自定义策略

Core 保留不可省略的基础过滤：排除 WinStrata 自身普通监视产生的内部写入、日志、IPC 等循环事件；外部进程对 WinStrata 文件、配置、数据库的修改仍记录；自我监视通过 StrataHealth 及必要故障日志实现。调试可手动启用自身细节监视，但必须防止递归。

StrataFilter 提供 GUI 及 Python/TS/JS 策略编辑，通过 StrataScript 运行。支持进程、软件、路径、事件、协议、IP、端口、网卡等包含/排除，去重、聚合、非关键指标采样、批量写入周期、缓冲、压缩及归档策略；显示过滤量、节省写入量和开销。脚本按批处理而非每事件启动解释器；失败回落基础机制并记录，不能绕过基础安全、数据完整性或风险包留存政策。未启用插件，基础保护仍生效。

### 8.4 I/O、硬件与资源保护

- 不持续无意义轮询、反复扫描、全盘哈希、重复读取或同步刷盘；事件驱动、增量索引、批量和顺序写入、有界内存缓冲、压缩、减少写入放大，兼顾异常断电数据完整性。
- StrataBudget 管理全局/插件 CPU、内存、磁盘 I/O、网络、存储、队列、后台并发和 GUI 刷新预算，Core 执行底层约束和最低保护。当前的工作者、队列和批量上限由 [Core 运行时](CORE-RUNTIME.md) 执行。计划 026 记录本进程 CPU 和驻留集，以及插件宿主已附着队列的暂停、恢复和丢失标记，不借降精度制造性能改善。磁盘 I/O、网络、存储和 GUI 刷新限额仍属于 [OI-051](../records/OPEN_ITEMS.md#oi-051)。行为见[资源限额](BUDGET.md)。
- StrataDisk 低频或按需读取 SMART、硬件健康、寿命及累计写入；区分本机逻辑写入和设备实际支持的物理写入计数。不得根据不支持指标估造磨损百分比。实际减少无效 I/O，不宣称可保证硬件无损耗。
- StrataHealth 实时诊断自身负载、丢失、队列、服务、驱动和数据库。计划 025 从插件宿主已附着的总线和调度器，以及插件故障状态，读取故障、队列、延迟和丢失，并把读数写入插件私有报告。服务、驱动、存储和界面读数仍属于后续计划，见[自身诊断](HEALTH.md)。插件禁用后，必要错误记录仍由 Core 保留。

### 8.5 本地安全、导入导出

可选加密数据库、抓包、快照、日志及备份；独立密码、自动锁定、轮换、密码修改、密钥保护和加密迁移。计划 013 用操作系统的 AES-256-GCM 和 PBKDF2-HMAC-SHA256 封装混合载荷和保险库。可迁移的保险库不使用 DPAPI。界面锁定显示仍属于计划 042。存储锁定会挡住读取，提交可以继续。插件通过授权数据接口、不直接持有核心密钥。不承诺抵御已获取内核权限的攻击者。加密密钥、口令和恢复信息留在本机。不自创密码算法。

支持完整与增量备份、恢复、按插件或时间范围导出、完整性检查、跨电脑迁移和带设备标识的历史合并。计划 013 写单文件完整包或增量包，核对每个文件的 CRC，恢复时不要求目标设备标识与包内记录相同。插件导出、按时间范围导出和明文导出仍属于计划 038 和 042。JSON/JSONL、CSV、HTML、PCAP/PCAPNG、SQLite 备份及专用 `.wstrata` 包仍是候选。导入验证格式、权限、版本、来源及恶意内容；防止路径越界、数据损坏及失效引用；加密内容不得未经确认以明文导出。所有操作本地进行。
