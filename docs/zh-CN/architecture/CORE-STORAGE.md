# Core 的用户配置与混合存储

[English](../../architecture/CORE-STORAGE.md) · [Rust 库](../../../core/src/lib.rs) · [计划 006](../roadmap/PLAN.md#pr-006) · [计划 012](../roadmap/PLAN.md#pr-012) · [计划 013](../roadmap/PLAN.md#pr-013) · [计划 014](../roadmap/PLAN.md#pr-014) · [计划 017](../roadmap/PLAN.md#pr-017)

PR 006 提供本地 Core 会话、运行设置及重新加载设置所需的存储。调用方使用实际运行进程的操作系统账号身份。Windows 从进程令牌读取用户 SID，Linux 使用有效 UID。

## 打开会话

以当前用户身份调用 `Core::open()`。Windows 将定位文件 `WinStrata/location.json` 和会话锁保存在用户的 Local AppData 目录。定位文件记录上次选择的存储位置，会话存续期间，操作系统保持 `session.lock` 的独占锁。默认数据根目录为 `D:\WinStrata\`。Linux 将定位文件保存在用户的 XDG 状态目录，首次打开时需显式选择数据目录。

受管文件为 `<所选根目录>/<用户标识>/core.json`，保存格式版本 1、所有者、工作区标识及设置。用户目录须保持私有。Core 检查所有者和权限，并拒绝路径重定向。用 `storage_state()` 区分 `Ready` 和 `NeedsDirectory { kind, detail }`。操作检测到卷失联、空间不足或无法写入时，会暂停持久化并停止实时模式。定位文件无法读取、格式无效或已有会话占用会话锁时，打开会话将返回错误。

## 修改配置与位置

- 初始会话停止实时监视，监视范围为空。用 `update_settings` 保存 `Settings` 中显式选择的 `monitored_roots` 和 `start_at_login`。监视目录必须为不含上级跳转的绝对路径。随登录启动默认为关闭，实际向操作系统注册启动项由相应集成负责。
- 选定至少一个监视目录后调用 `start_live`。用 `run_state()` 读取 `Stopped`、`Live` 或 `History` 状态。可调用 `stop` 停止会话，或调用 `enter_history` 退出实时模式并进入历史模式。重新打开会话后，监视仍为停止状态。
- 停止实时监视后，用 `select_directory` 显式选择目录。迁移时，Core 复制当前用户的普通文件和目录，重新枚举两侧并校验名称、类型及字节内容，成功后才原子更新定位文件。目录树重叠、链接或目标内容冲突均会被拒绝。迁移保留原文件。
- 原工作区不可用时，可在它恢复后重新选择原根目录。Core 会核对工作区标记是否与定位文件一致。若要在其他位置重新开始，须显式调用 `select_empty_directory`，选择独立且用户子目录为空的位置。原卷保留先前数据。原工作区仍可访问时应使用经过验证的迁移流程。

设置和定位文件的 JSON 上限为 64 KiB。未知版本、损坏内容以及已有的宽泛权限会导致操作失败，已有文件可供恢复。选择空监视范围会停止实时状态。此次迁移验证普通文件的内容、目录结构及用户隔离，遇到 NTFS 命名数据流会停止。Windows 文件系统实测覆盖 NTFS；ReFS 尚未实测。空间检查比较当前账户可用字节数与本次写入的需求，实际写入错误也会暂停持久化。

## 引导与模式

计划 017 把 `onboarding.json` 放在 `core.json` 旁边。它不改变 `core.json` 里的设置形状。`RunState` 仍是 `Stopped`、`Live` 或 `History`。暂停是单独的内存标志，因此新会话启动时处于停止且未暂停。`start_live` 仍然只改变这个标志。`begin_live` 还会启动所选的文件和注册表监视，并写入一条模式对象。离开实时模式时，历史和停止会落盘一条缺口，并且只在驱动已有订阅时要求服务释放。暂停会停止用户态监视，不要求释放驱动。丢失标记使用 `GapReason::Lost`，不会被改写成暂停。加密必须在第一次混合提交之前启用。官方界面在进程内持有一个 Core，因为运行标志和保险库密封都在内存里。启用选择不调用 `enable`，也不启动计划 018–047。界面向 `Core::open_at` 传入的默认目录为空，因此缺失的选择不会被换成 `D:\WinStrata\` 或 `C:\`。

## 混合记录

计划 012 在已经选定的用户目录中保存五类记录和一份索引。`Core::open_hybrid` 打开 `<用户目录>/data/{databases,events,metrics,captures,snapshots,indexes}`。`core.json` 仍与 `data` 同级。调用方用 `Batch` 组装一次变更，再调用 `Core::commit_hybrid`。总线不订阅存储，也不写磁盘；需要保留的事件由调用方放入批次。

每类载荷只写入对应目录的分段 `s{编号}.wsg`。`indexes/journal.wsj` 记录提交序号、分段水位，以及每条记录的位置和 CRC，不复制载荷。默认分段为 1 MiB，允许 256 字节到 16 MiB。单条记录可以独占一个超过该上限的分段。单条载荷上限为 1 MiB，单次提交编码上限为 8 MiB，对象正文上限为 256 KiB。打开时根据日志重建内存索引。不完整的日志尾部会被截断。CRC 完整但载荷校验或结构失败的提交，连同它之后的提交一起回退。查询会重新读取字节，并拒绝损坏的内容。同一次进程中的写入失败会删除新建分段，并把已有分段恢复到写入前的长度。

- 结构化目录保存对象和关系。正文相同的对象不会再次追加，相同关系也不会增加提交。
- 事件保存协议 JSON。同一来源的重复序号会在写入前被拒绝。
- 时序使用时间戳的二阶差分和数值差分，并用 zigzag 变长整数编码。
- 抓包写入小端 PCAPNG。节头块魔数为 `0x0A0D0D0A`，接口块使用纳秒时间分辨率，增强包块的注释保存风险标签。没有标签的包在任何写入之前被拒绝。时间戳必须大于或等于 0。链路类型变化时更换分段。
- 快照只保存路径和状态标识，不保存文件内容，也不根据这些路径写文件系统。完整快照没有基线，增量快照指向基线。`materialize_snapshot` 沿这条链合并路径。空路径、`..`、NUL、超过 4096 字节的路径、重复路径和超过 8192 项都会被拒绝。

`set_retention` 按 `DataClass` 保存天数。`None` 表示继续永久保留，`Some(0)` 会被拒绝。这个调用不删除数据。清理和配额执行属于计划 030。`capacity` 分别统计六个目录里普通文件的字节，抓包单独计数。`reserve` 使用既有的 `storage::capacity`。用 `u64::MAX` 调用会返回空间不足，测试没有为此写满物理磁盘。卷错误会暂停 Core 会话并停止实时模式。`InvalidInput` 和 `InvalidData` 不暂停会话。

计划 006 的迁移会复制用户目录中的普通私有文件。混合存储文件在权限为 `0600` 且没有额外硬链接时，会随该用户目录一起迁移。加密工作区的 `vault.wsv` 也随这些文件复制。复制之后源目录仍在，目标目录用同一把密钥打开。

## 加密、备份与恢复

加密默认关闭，直到调用 `enable_encryption`。实时监视进行中、保险库已存在，或混合存储已经有提交时，这个调用会被拒绝。口令为 8 到 1024 字节。自动锁定为 0 秒到 7 天。`vault.wsv` 与 `core.json` 同级，权限 `0600`，上限 64 KiB。它保存 PBKDF2-HMAC-SHA256 参数、口令校验值、封装后的数据密钥和 16 字节设备标识。迭代次数必须是 600,000。未启用加密时，同一设备标识写在 `device.wsd`。

Linux 使用系统 OpenSSL 3 的 `libcrypto.so.3` 封装记录。Windows 使用 CNG 的 `BCrypt`。两边都是 AES-256-GCM。本仓库不实现分组密码，也没有增加密码学包。不使用 AF_ALG。可迁移的保险库不使用 DPAPI，因为它把密文绑在一个 Windows 配置文件上，另一台电脑无法恢复。这项选择记为 AS-009。

封装记录由 `WSE1`、12 字节 nonce、密文和 16 字节标签组成。关联数据绑定用户、工作区、类别、分段和偏移，因此被移动或对调的记录无法通过认证。日志里的 CRC 覆盖落盘的密文。抓包前导仍可在没有密钥时读取。包字节在封装记录内部。锁定后的查询返回 `PermissionDenied`，文本是 `storage is locked`。提交仍然加密，不刷新空闲计时，也不停止 `RunState::Live`。自动锁定在用户读取时检查。进程重启后没有数据密钥，`open_hybrid` 保持锁定，直到 `unlock`。锁定错误不暂停会话。错误口令返回 `password is not valid`，不会被报成保险库损坏。

`change_password` 重新封装当前数据密钥。`rotate_keys` 生成新的数据密钥，按原长度重写每条被引用的记录，再重新封装保险库。重写和重新封装之间如果崩溃，新密文可能还对应旧封装。重新封装在本进程内失败时，Core 会尝试写回旧密钥。这里不把轮换说成崩溃安全。

`backup_full` 和 `backup_incremental` 在用户目录之外写一份 `WSB1` 包。包内复制普通文件，并为每个文件保存 CRC。增量包记录相对同一用户和工作区的完整包发生变化的文件，以及自那份完整包以来删除的路径。实时监视进行中时拒绝备份和恢复。锁定期间允许备份，包内保持密文。恢复核对用户、工作区、配置和每个文件的 CRC，并在写入之前拒绝 `..`。记录的设备标识不必与目标机器相同。这里没有明文导出、插件导出、按时间范围切分或删除配额。它们仍属于计划 038、042 和 030。

## 插件控制文件

`Core::open_at` 已公开，调用方可以指定定位目录。`Core::open()` 仍使用操作系统定位目录。选择存储后，`Core::open_plugins` 创建 `<用户>/plugins`。宿主状态、历史、包、恢复副本和插件私有目录都是该目录中的普通文件。它们不写入 `vault.wsv`。本计划不加密这些文件。生命周期见[插件宿主](PLUGINS.md)。

## 验证范围

在 Linux 和 Windows 上运行 `cargo test --locked -p winstrata-core`，覆盖启动、设置、重启、存储失联与恢复、私有目录访问和 Core 配置迁移。工作区 CI 在 Linux 与 Windows Server 2022 上运行测试。计划 012 覆盖混合存储的写入、查询、分段、索引、容量和损坏回退。计划 013 覆盖口令、锁定、加密和解密、备份、恢复以及跨位置迁移。Windows Server 2022 在送审头 `36b5cd688afa2f9690f4a634d0a4c57ec6eba7cd` 上运行了这些测试并通过。该作业不是 Windows 10/11 客户端。ReFS、第二台物理设备、第二个操作系统账户、界面锁定、崩溃安全的密钥轮换和 E2E-10 仍未完成。main `a2471d5fc13f0a307ee39d2629c454aea4537809` 随后在 Windows 工作区检查中，`process::tests::real_process_tree_pid_lifecycle_and_dedup` 失败。见 [ERR-013](../records/modules/core.md#err-013)。那次运行不是该 main 提交的加密验收通过。见[工程记录](../records/STATUS.md)和[数据架构](DATA.md#section-8)。
